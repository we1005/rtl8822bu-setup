# 过程与修改归属

## 哪张网卡的源码被修改了？

| 对象 | 实际做的工作 | 是否改内核源码 | 是否需要迁移到外置 USB 适配器的新主机 |
|---|---|---|---|
| 内置 MediaTek MT7902 Wi-Fi，PCI 14c3:7902 | 使用已有 morrownr/mt76；本轮未修改它的 Wi-Fi 代码 | 本轮没有 | 仅当新主机也有同款内置卡、且需要该驱动时另评估 |
| **内置 MediaTek MT7902 蓝牙，USB 0e8d:7902** | 在 Ubuntu 7.0 基线 btmtk.c / btmtk.h 上回移植 MT7902 支持，扩展 DKMS | **有：实际修改的是这里** | **不能用于 Realtek USB 设备** |
| 外置 Realtek RTL8822BU Wi-Fi，USB 0bda:b82c | 编译并临时测试新版 rtw88，最后恢复系统原生 rtw88_8822bu | 没有保留修改版内核源码/模块 | 迁移原生驱动检查和配置策略，而不是搬旧 .ko |
| 外置 Realtek 蓝牙 | 使用系统 btusb / btrtl 与现有固件 | 没有 | 检查目标系统驱动、固件、控制器和真实配对 |

内置蓝牙项目中的 `src/` 是 6.17 基线，新增的 `src-7.0/` 是 7.0 基线。原厂驱动本来就在 Linux 源码中；这些目录是为特定系列内核编译替换 btmtk 的源码副本，不是外置 Realtek 驱动。

回移植仍来自 MediaTek 的上游提交 `aab25984e559`，仅在相应内核源码里加入 MT7902 芯片分支和固件路径定义。它解决的是 `Unsupported hardware variant (00007902)`。包装、构建和维护脚本由项目新增；没有把上游两行补丁说成重新开发了一整套驱动。

## 外置设备的适配过程

1. 使用 lsusb / sysfs 确认 USB 0bda:b82c，实际 Wi-Fi 驱动为 rtw88_8822bu，蓝牙与 Wi-Fi 位于同一 USB 复合设备下。
2. 确认当前内核已有支持，先扫描和连接，不因为接口未关联时显示 DOWN 就判断缺驱动。
3. 实际测试遇到省电/掉信标和一次无人拔插的整机 USB 重新枚举。关闭连接省电、仅禁用这个 USB 设备的 runtime autosuspend 后，负载阶段没有再复现同类掉线。
4. 临时编译并加载 lwfinger/rtw88 作对照，最终原生驱动在测试网络下也达到约 267Mbps 上行、217Mbps 下行，因此保留系统自带驱动。
5. 两张网卡同网段时，抓包发现 USB DNS 请求的回包进入内置卡。原主机增加接口级 ARP、源地址路由和 NetworkManager dispatcher 后，两路独立 DNS / HTTPS 均通过，重启后也自动恢复。
6. 外置蓝牙完成手机配对、OBEX 文件发送、回显；完成休眠、启动和真实插拔测试。最后一轮重启后联系手机曾暂时失败，控制器仍正常开启。后续在同一 boot 中完成复测：两套控制器各 5 发 5 收；内置发送 4,154 字节、外置重发 4,163 字节，均返回 Status=complete。外置首次出现的 Forbidden 和早先不可达样本保留，本次恢复过程中未重装/重载驱动，也未重新配对。

## 迁移时复用什么？

复用硬件识别方法、原生驱动/固件检查、电源配置、按需的多网卡路由策略和验收流程。本组件把这部分整理成动态发现和可卸载的 Python 程序。

不复制原主机网卡名、hci 编号、IP、SSID/密码、固定路由表号、配对密钥或面向 6.17 / 7.0 的 btmtk.ko。新机器的蓝牙配对记录也属于新控制器环境，应通过其蓝牙界面重新确认，不搬 `/var/lib/bluetooth`。

历史成绩只描述已测机器和网络。特定旧接入点的 5GHz 四次握手问题仍保留为兼容限制；手机 5GHz 热点可用并不意味着每台 AP 都已测试。
